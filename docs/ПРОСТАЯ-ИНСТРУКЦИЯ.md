# Простая инструкция (для человека, а не для инженера)

Этот файл — «для чайников». Если непонятно что-то в `README.md` или в `docs/` — читайте здесь. Здесь только то, что реально нужно сделать руками, шаг за шагом, без объяснений «почему».

Если бот уже настроен и просто перестал работать — сразу смотрите раздел [10. Частые проблемы](#10-частые-проблемы).

---

## 1. Что вообще нужно установить на компьютер

Три программы, один раз:

1. **Docker Desktop** — https://www.docker.com/products/docker-desktop/
   Скачать, установить, запустить. В трее/меню должен появиться значок кита. Бот работает внутри Docker — без него ничего не запустится.
2. **Node.js** (версия 20 или новее) — https://nodejs.org/ (кнопка «LTS»)
   Нужен только для пары служебных команд (настройка базы данных).
3. **Git** — https://git-scm.com/downloads
   Нужен, чтобы скачать и обновлять код проекта.

Проверить, что всё встало, можно в терминале (Terminal на Mac, PowerShell на Windows):

```bash
docker --version
node --version
git --version
```

Если каждая команда что-то печатает (не «command not found») — всё установлено.

## 2. Что нужно завести заранее (аккаунты и ключи)

- **Telegram-бот и его токен** — создаётся через [@BotFather](https://t.me/BotFather) в Telegram (команда `/newbot`). BotFather выдаст длинную строку вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — это и есть токен.
- **Ваш личный Telegram ID (число)** — узнать у [@userinfobot](https://t.me/userinfobot), просто напишите ему что угодно.
- **Ключ Claude API** (необязательно) — на https://console.anthropic.com/. Стоит денег. Без него бот тоже работает, просто новости сортируются проще (по ключевым словам, а не «умно»).

## 4. Настроить секретный файл `.env`

Этот файл хранит все пароли и токены. Он **никогда** не попадает на GitHub (сделано специально, для безопасности).

1. Скопируйте файл `.env.example` и переименуйте копию в `.env`.
2. Откройте `.env` в любом текстовом редакторе и заполните:

| Строка                     | Что туда вписать                                                             |
| --------------------------- | ----------------------------------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN`        | Токен от BotFather (шаг 2)                                                    |
| `TELEGRAM_ALLOWED_USER_ID`  | Ваш числовой ID от @userinfobot (шаг 2)                                       |
| `CLAUDE_API_KEY`            | Ключ Claude, если есть. Если нет — оставьте пустым, ничего не сломается       |
| `POSTGRES_PASSWORD`         | Придумайте любой пароль (просто набор символов, никому не сообщать)           |
| `N8N_ENCRYPTION_KEY`        | Придумайте любую длинную случайную строку (например 32 случайных символа)     |

Остальные строки трогать не нужно — там уже стоят рабочие значения по умолчанию.

**Важно:** если вы уже настраивали бота раньше на другом компьютере — не придумывайте новый `.env`, а скопируйте старый (флешкой, через AirDrop и т.п.). Иначе бот «забудет» токен и настройки.

## 5. Запустить всё

```bash
docker compose up -d
docker compose ps
```

Второй командой проверяем — у всех сервисов (`postgres`, `rsshub`, `n8n`, `helper-api`) в колонке `STATUS` должно быть `Up` (и `healthy`, если написано). Если что-то не поднялось — подождите полминуты и повторите `docker compose ps`, при первом запуске образы ещё скачиваются.

Теперь настроить базу данных (делается один раз, при первом запуске):

```bash
npm run db:migrate
npm run db:seed
```

## 6. Настроить n8n (мозг бота)

n8n — это программа, которая всё связывает. Открывается в браузере: **http://localhost:5679**

При первом заходе попросит создать аккаунт-владельца (свой e-mail/пароль, только для входа в n8n на этом компьютере — к Telegram отношения не имеет).

### 6.1 Добавить пароли (credentials)

В n8n → **Credentials → New**, три штуки:

1. **Telegram API** — вставить `TELEGRAM_BOT_TOKEN` из `.env`.
2. **Postgres** — host `postgres`, база `tg_news`, логин/пароль из `.env` (`POSTGRES_USER`/`POSTGRES_PASSWORD`).
3. **HTTP Header Auth** (для Claude, если есть ключ) — заголовок `x-api-key` = `CLAUDE_API_KEY`.

Подробности — `n8n/credential-setup.md`, но обычно этих трёх шагов хватает.

### 6.2 Загрузить сценарии работы бота (workflows)

В папке `n8n/workflows/` лежат 13 файлов `.json` — это готовые «сценарии» (добавить канал, разослать новости и т.д.). Их нужно загрузить в n8n:

**Workflows → Import from File** → выбрать файл → повторить для каждого из 13 файлов.

После загрузки каждого файла — открыть его и убедиться, что на всех цветных блоках выбран нужный пароль из шага 6.1 (обычно n8n подставляет сам, но лучше проверить).

### 6.3 Включить нужные сценарии

Включить (переключатель справа сверху каждого workflow) вот эти:

- `health_check`
- `poll_rss_sources`
- `deduplicate_posts`
- `classify_heuristic`
- `send_instant_alerts`
- `daily_digest`
- `telegram_commands`
- `error_handler`

`classify_with_claude` **не включать**, если нет ключа Claude — эта роль уже выполняется `classify_heuristic` бесплатно.

## 7. Подключить Telegram к боту (webhook)

Боту нужен публичный адрес в интернете, чтобы Telegram мог присылать ему сообщения. Для этого используется бесплатная программа **ngrok**.

1. Установить: https://ngrok.com/download (нужна бесплатная регистрация)
2. Запустить туннель:
   ```bash
   ngrok http 5679
   ```
3. В окне ngrok появится адрес вида `https://xxxx.ngrok-free.dev` — скопировать его.
4. Вписать этот адрес в `.env`, в строку `WEBHOOK_URL` (в конце добавить `/`).
5. Перезапустить n8n, чтобы он подхватил новый адрес:
   ```bash
   docker compose up -d n8n
   ```
6. Открыть в n8n workflow `telegram_commands`, найти узел (блок) **Telegram Trigger**, скопировать его webhook-адрес (показан прямо в блоке).
7. Сообщить Telegram, куда слать сообщения (замените `<ТОКЕН>` и `<АДРЕС>`):
   ```bash
   curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=<АДРЕС>"
   ```

**Важно:** у бесплатного ngrok адрес меняется при каждом перезапуске — шаги 7.2–7.7 придётся повторять каждый раз, когда вы заново включаете бота на этом компьютере. Есть способ сделать адрес постоянным (бесплатный статический домен ngrok) — если хочется, попросите настроить отдельно.

## 8. Добавить каналы и проверить, что бот работает

В Telegram напишите своему боту:

```
/help
/add_source https://t.me/durov
```

(замените на любой реальный публичный канал). Через 10–20 минут в канале должны появиться новости — либо мгновенно (если важные), либо в ежедневном дайджесте в 09:00 по Бишкеку.

Проверить руками, не дожидаясь, что что-то реально пришло, можно так:

```bash
docker compose exec postgres psql -U tg_news -d tg_news -c "SELECT count(*) FROM posts WHERE created_at > now() - interval '1 hour';"
```

Число больше нуля — бот реально что-то скачал.

## 9. Перенос на другой компьютер

Если нужно продолжить работу на другом ноутбуке (например, этот не может быть включён постоянно):

1. На старом компьютере скопируйте файл `.env` (флешкой/AirDrop — **не** через мессенджеры и почту).
2. На новом компьютере повторите шаги 1, 3 (склонировать код), 4 (вставить скопированный `.env`), 5 (запуск).
3. Шаг 6 (credentials + импорт workflows) придётся повторить — n8n на новом компьютере «пустой», ничего не помнит с прошлого.
4. Шаг 7 (ngrok) тоже заново — адрес каждый раз новый.

Старые новости/каналы **не переносятся** сами по себе (база данных остаётся на старом компьютере) — бот на новом месте начнёт собирать всё заново, это нормально.

## 10. Частые проблемы

| Проблема                                              | Что делать                                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| `docker compose up -d` пишет ошибку про занятый порт   | Что-то другое уже использует этот порт. Поменяйте `N8N_PORT` или `POSTGRES_PORT` в `.env`         |
| Бот не отвечает на `/help`                              | Проверьте шаг 7 — скорее всего адрес ngrok устарел (перезапускался) и Telegram шлёт в никуда      |
| `docker compose ps` показывает не `healthy`             | Подождите минуту, ещё раз `docker compose ps`. Если не помогло — `docker compose logs <сервис>`   |
| `npm run db:migrate` не подключается к базе             | Проверьте, что `docker compose ps` показывает `postgres` как `Up`, и подождите пару секунд после запуска |
| Канал добавился, но новостей нет                       | Подождите 10–20 минут (бот проверяет каналы раз в 10 минут), затем проверьте раздел 8             |

Более подробный (технический) список — `docs/troubleshooting.md`.
